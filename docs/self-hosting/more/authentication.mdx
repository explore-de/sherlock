<Note>Microsoft Entra ID is supported for single sign-on. Discuss additional authentication needs with your [instance administrator](/docs/connections/request-new)</Note>
<Warning>If you're switching from non-auth, delete the Sherlock cache (the `.sherlock` folder) before starting.</Warning>

Sherlock has built-in authentication that gates access to your organization. OAuth, email codes, and email / password are supported. To enable authentication, set the `SHERLOCK_AUTH_ENABLED` environment variable to `true`.
When authentication is enabled:

- [Connection managment](/docs/connections/overview) happens through the UI
- If you're in single-tenant mode, the first user to register will be made the owner of the default organization. Check out the [roles page](/docs/more/roles-and-permissions) for more info on the different roles and permissions
- After that owner exists, anyone who signs in through an identity provider — Microsoft Entra ID, GitHub, Google or an email code — joins the default organization as a member. Restricting who may sign in is the identity provider's job: in Entra, for example, by requiring app role assignment
- Email / password accounts are the exception. That sign-up verifies no identity, so such an account gains **no** access on its own and must be invited. Disable it with `AUTH_CREDENTIALS_LOGIN_ENABLED=false` when an identity provider is your access boundary

# Authentication Providers

<Warning>Make sure the `AUTH_URL` environment variable is [configured correctly](/self-hosting/configuration) when using Sherlock in a deployed environment.</Warning>

To enable an authentication provider in Sherlock, configure the required environment variables for the provider. Under the hood, Sherlock uses Auth.js which supports [many providers](https://authjs.dev/getting-started/authentication/oauth). Submit a [feature request on GitHub](/docs/connections/request-new) if you want us to add support for a specific provider.


## Email / Password
---
Email / password authentication is enabled by default. It can be **disabled** by setting `AUTH_CREDENTIALS_LOGIN_ENABLED` to `false`.

## Email codes
---
Email codes are 6 digit codes sent to a provided email. Email codes are enabled when transactional emails are configured using the following environment variables:

- `SMTP_CONNECTION_URL`
- `EMAIL_FROM_ADDRESS`


See [transactional emails](/self-hosting/more/transactional-emails) for more details.

## GitHub
---

[Auth.js GitHub Provider Docs](https://authjs.dev/getting-started/providers/github)

**Required environment variables:**
- `AUTH_GITHUB_CLIENT_ID`
- `AUTH_GITHUB_CLIENT_SECRET`

## Google
---

[Auth.js Google Provider Docs](https://next-auth.js.org/providers/google)

**Required environment variables:**
- `AUTH_GOOGLE_CLIENT_ID`
- `AUTH_GOOGLE_CLIENT_SECRET`

## Microsoft Entra ID
---

[Auth.js Microsoft Entra ID Provider Docs](https://authjs.dev/getting-started/providers/microsoft-entra-id)

**Required environment variables:**
- `AUTH_ENTRA_CLIENT_ID`
- `AUTH_ENTRA_CLIENT_SECRET`
- `AUTH_ENTRA_TENANT_ID`

All three must be set; the provider stays disabled otherwise. The issuer is
derived from the tenant id as `https://login.microsoftonline.com/<tenant>/v2.0`,
so a single-tenant registration needs no further configuration.

Register the redirect URI in your Entra application as
`<AUTH_URL>/api/auth/callback/microsoft-entra-id`, and grant the delegated
Microsoft Graph permissions `openid`, `profile`, `email` and `User.Read`.

Everyone Entra lets through joins the default organization as a member, so the
application registration is the access boundary: keep it single-tenant, and set
"Assignment required" plus a security group if only part of the tenant should
reach Sherlock. Set `AUTH_CREDENTIALS_LOGIN_ENABLED=false` so no one can bypass
it by registering an email and password instead.

# Troubleshooting

- If you experience issues logging in, logging out, or accessing an organization you should have access to, try clearing your cookies & performing a full page refresh (`Cmd/Ctrl + Shift + R` on most browsers).
- Still not working? Reach out to us to your [instance administrator](/docs/connections/request-new)
